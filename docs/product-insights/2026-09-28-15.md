## Prioritized recommendations

### 1. Fix or verify the funnel instrumentation (highest priority)
Two rows are internally inconsistent, so funnel conclusions are unreliable until this is resolved.
- `p-median-us`: `solveCompleted` (237) is greater than `solveTriggered` (214).
- `max-coverage-us`: `solveTriggered` is 0 but `solveCompleted` is 4.

A completed solve should normally follow a trigger. The aggregates don't say why the counts disagree. Possible causes include events fired from different code paths (for example, a re-solve or a cached path that doesn't emit the trigger event), or a differing time window for each event. The aggregates can't confirm any of these. Recommend auditing where each event is emitted and making the definitions consistent.

### 2. Investigate why runtime and cache metrics are all zero
`runtimeP50`, `runtimeP95` and `cacheHitRate` are all 0, even though solves completed (at least 244 across models). A p50 runtime of exactly 0 is implausible for real CBC solves. This more likely means the metrics aren't being populated than that solves were instantaneous. Until it's confirmed, don't use these fields for performance decisions. Recommend checking that runtime and cache properties are captured on the completion event and included in the aggregation.

### 3. Investigate the export step: zero exports across every model
`exported` is 0 for all four models, including 237 completed `p-median-us` solves. This is either a real drop-off after solve or an untracked event. Recommend first confirming that the export event fires. If it does, look at how discoverable export is after a solve.

### 4. Look at stale-without-resolve behavior
The stale-resolve rate is about 8.8%. The aggregates don't define the denominator, and they don't say whether the rest of the stale scenarios were left unresolved or simply never became stale. Recommend defining the metric explicitly (stale scenarios viewed vs. re-solved). If most stale scenarios stay unresolved, consider a more prominent re-solve prompt on the stale badge in Studio and Compare.

### 5. Solve failures and rejections: no action needed
Both maps are empty, so no failures or rejections were reported this week. Given the instrumentation gaps above, confirm that failure and rejection events are wired up. An empty map is only good news if the events are emitted at all.
