**1. two-echelon-gold-au: complete drop-off at the solve step (actionable now).** The one scenario created for this model was never solved (`solveTriggered: 0`). This is a full funnel stop, not a partial drop-off. With only one created scenario the cause can't be diagnosed from aggregates alone (could be UI friction, could be the user abandoning the session, could be the model being deliberately hidden/deprioritized per current chapter-visibility settings) — but a 0-of-1 solve rate on a model that's supposed to be reachable is worth a manual click-through check before next week's collection, since we have no data yet on why.

**2. p-median-us: created (2) is far smaller than solveTriggered (10) — repeated re-solving of the same scenarios, not new scenario creation (watch-and-recollect).** This is consistent with normal iterative use (a student adjusting inputs and re-solving), but it also means this week's "solve" activity is concentrated in very few scenarios. Worth confirming next week whether this pattern holds — if `created` stays flat while `solveTriggered` keeps climbing, it may indicate the create-flow itself is a barrier that engaged users route around instead of using.

**3. p-median-us: exported (1) vs. solveCompleted (10) — a 10% export follow-through rate (watch-and-recollect).** Only 1 of 10 completed solves led to an export. Exports are optional (viewing results in-app is a valid end state), so this alone is not proof of a problem, but it's the largest completed→exported gap in this week's data and worth tracking across a few more weeks before concluding whether export is undiscoverable or simply unneeded by most users.

**4. two-echelon-jade-us: solveCompleted (2) exceeds solveTriggered (1) (actionable now — data-quality flag, not a product signal).** A completed count higher than the triggered count in the same window is not logically possible for a single week's funnel and points to an aggregation or event-boundary issue (e.g. a solve triggered in a prior period completing this period, or a double-count on completion) rather than real usage. Recommend checking the event/aggregation pipeline for this model before trusting any funnel numbers from it going forward.
