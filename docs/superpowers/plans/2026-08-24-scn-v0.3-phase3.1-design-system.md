# SCN v0.3, Phase 3.1 — SCN Design Wireframes Theme → Workspace, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development-style single-task dispatch via this repo's agent-team model (see AGENTS.md) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-skin the built Workspace shell (and only Workspace) with the real SCN Design Wireframes token set (`/Users/shubhamkr/Downloads/SCN Design Wireframes/styles.css`) — colors, Barlow/Barlow Condensed fonts, literal 0px radius — via a scoped CSS class, mirroring the existing `.studio-lab` precedent. Then verify structural fidelity against the 5 annotated wireframe screens live in a browser.

**Architecture:** New `.scn-theme` CSS class in `index.css` overrides the same HSL custom-property names the existing `@theme inline`/shadcn system already reads (`--background`, `--primary`, `--radius`, etc.) — zero component markup rewrites needed for color/radius. A new `--app-font-heading`/`font-heading` utility is added alongside the existing `--app-font-sans/serif/mono` pattern for Barlow Condensed headings. The class is applied once, to `Workspace.tsx`'s root shell div, so Landing/auth/Studio/Compare are unaffected.

**Tech Stack:** Tailwind v4 (`@theme inline`, CSS custom properties), React + Vite, Vitest + RTL.

## Global Constraints

- Scope: Workspace shell + its shared/tab components only. Do not touch Landing.tsx, auth pages, Studio.tsx, Compare.tsx.
- Radius: literal `0` (not the wireframe's own `--radius-sm/md/lg` 2/4/7px tokens) — user-confirmed decision.
- Do not change the base `--spacing` token (Tailwind's existing 4px scale stays) — see design spec's rationale.
- Do not remove or alter `.studio-lab`/`--arc-*` (out of scope, Studio.tsx still lives until Phase D).
- No dark-mode variant for `.scn-theme` — none exists in the wireframe.
- Source design spec: `docs/superpowers/specs/2026-08-24-scn-v0.3-phase3.1-design-system-design.md` — full token mapping table lives there; this plan's Task 1 code below already applies it verbatim.

## Post-implementation: manual browser fidelity verification (controller step, not a subagent task)

After Task 1 lands, passes its own test gate, and is committed — per this repo's established practice (e.g. the Phase 4 exit check, Chapter 10's rounds), the controller (not a dispatched agent) runs a live browser check via `claude-in-chrome` against local dev servers:

2. Log in, open a p-median-us scenario in Workspace, navigate through the 5 wireframe-covered surfaces: Warehouses tab, Solve dialog, Output Map tab, Reports tab, and a stale-scenario state.
3. Compare each against its corresponding wireframe screen (`/Users/shubhamkr/Downloads/SCN Design Wireframes/Wireframes.dc.html` screens 1a·1 through 1a·5): background/surface/text/accent colors read as the new palette, radius reads as sharp/square everywhere, headings render in the condensed font, body text renders in Barlow.
4. Fix any real, concrete mismatch found directly (small, targeted commits) — this is a verification pass, not a new open-ended design task; only fix what's actually wrong against the wireframe, don't invent extra polish.
5. Record the outcome in `CLAUDE.md`'s v2 progress log, same convention as every other phase in this file.

This step is deliberately not a plan Task/subagent dispatch — visual comparison against a live rendered page needs a real browser, which only the controller's `claude-in-chrome` tools reach; a subagent has no way to independently confirm what a human/controller sees.
