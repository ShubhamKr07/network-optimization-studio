# SCN v0.3, Task C4.2 — Copy Map to Clipboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: This plan is executed via the **agent team** (`frontend-engineer` role) — a single frontend-only feature, no backend involvement. Each task below is still its own commit with its own tests. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add "Copy to clipboard" and "Download PNG" actions to `OutputMapTab.tsx`, implementing the already-decided design (`docs/superpowers/specs/2026-08-24-scn-v0.3-c42-clipboard-copy-design.md`) on top of the already-completed research spike (`docs/superpowers/specs/2026-08-24-copy-map-clipboard-spike.md`).

**Architecture:** New pure-function lib module (`lib/copyMapToClipboard.ts`) wraps `html-to-image`'s `toBlob` and the eager-capture Clipboard API pattern the spike requires; `OutputMapTab.tsx` gets a ref on its existing map container div and two new buttons that call into that lib module.

**Tech Stack:** React (unchanged), `html-to-image` (new dependency), vitest/RTL (unchanged).

## Global Constraints

- **Library and version, already decided, do not re-derive**: `html-to-image` `^1.11.13`, added to `artifacts/studio/package.json`'s `dependencies`.
- **Eager-capture pattern is a hard correctness requirement, not a style preference** (per the spike's WebKit bug #222262 finding): `navigator.clipboard.write([...])` must be called synchronously inside the triggering click handler's call stack, with the async capture passed as an *unawaited* `Promise<Blob>` value inside the `ClipboardItem` constructor — never `await capture(); await clipboard.write(...)`. This is the one piece of code in this plan where getting the shape wrong produces a bug that only reproduces on Safari, not in a Chrome-only local dev check — copy the exact pattern from the spike doc, don't rewrite it "more simply."
- **One capture call serves both actions**: `copyMapToClipboard` and `downloadMapAsPng` both go through `captureMapAsBlob` — a copy failure falls through to reusing that same blob for a download, not a fresh capture.
- **The capture target is the existing `flex-1 min-h-0` div** in `OutputMapTab.tsx` — already isolated from the toggle-checkbox row by the current layout (two sibling divs, not nested). No `filter`/exclusion option needed.
- **Download mechanism mirrors `exportEntity.ts`'s existing pattern exactly**: `URL.createObjectURL` → synthetic `<a download>` → `.click()` → `URL.revokeObjectURL`. Don't invent a different download mechanism.
- **Feature-detection is static, not per-click**: whether the "Copy to clipboard" button renders at all is decided once per mount (`useState(() => isClipboardImageWriteSupported())`), not re-checked on every render or every click.
- Test locations, unchanged: frontend tests in `artifacts/studio/src/__tests__/`.

- [ ] **Step 4: Implement `copyMapToClipboard.ts`**

```ts
import { toBlob } from "html-to-image";
import { toast } from "@/hooks/use-toast";

// C4.2 — implements the eager-capture pattern the spike (docs/superpowers/
// specs/2026-08-24-copy-map-clipboard-spike.md) found is REQUIRED for
// Safari/Firefox correctness (WebKit bug #222262): navigator.clipboard.write
// must be called synchronously inside the triggering click handler, with the
// async capture passed as an unawaited Promise<Blob> value inside the
// ClipboardItem constructor — not awaited beforehand. Do not "simplify" this
// to `await capture(); await clipboard.write(...)` — that form only fails on
// Safari, so it will look correct in a Chrome-only local check.

export async function captureMapAsBlob(node: HTMLElement): Promise<Blob> {
  const blob = await toBlob(node);
  if (!blob) throw new Error("capture failed");
  return blob;
}

export function isClipboardImageWriteSupported(): boolean {
  return (
    typeof navigator.clipboard?.write === "function" &&
    typeof (globalThis as { ClipboardItem?: unknown }).ClipboardItem === "function"
  );
}

export async function downloadMapAsPng(node: HTMLElement): Promise<void> {
  const blob = await captureMapAsBlob(node);
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url;
  a.download = "output-map.png";
  a.click();
  URL.revokeObjectURL(url);
}

export async function copyMapToClipboard(node: HTMLElement): Promise<"copied" | "downloaded"> {
  try {
    await navigator.clipboard.write([
      new ClipboardItem({
        "image/png": captureMapAsBlob(node),
      }),
    ]);
    return "copied";
  } catch {
    await downloadMapAsPng(node);
    return "downloaded";
  }
}
```

(The `toast` import is unused in this file's current form — Task 2's click handler in `OutputMapTab.tsx` owns the toast call per the design doc, not this lib module, so remove the unused `toast` import here rather than leaving dead code. This lib module's job is capture/copy/download mechanics only, not UI feedback.)

    await downloadMapAsPng(mapRef.current);
