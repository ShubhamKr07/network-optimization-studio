## Task T2 — Output-Map floating metric overlay (item 2)

**Role:** frontend-engineer. **Files:** `artifacts/studio/src/components/workspace/tabs/OutputMapTab.tsx`, `artifacts/studio/src/__tests__/OutputMapTab.test.tsx`.

Read `OutputMapTab.tsx` first: it already receives a `result` prop (fed from `displayedResult` by Workspace), renders a toggles row + `copyDownloadButtons` + a map container `<div>` that wraps `NetworkMap`. The overlay goes INSIDE that map container, absolutely positioned.

- [ ] **Step 1 — failing test.** With a `result` whose `objective` and `metrics.weightedAvgDistance` are set, the tab renders an overlay (`data-testid="output-map-metric-overlay"`) containing the formatted objective and the weighted-avg-distance with the model's unit. With `result == null`, the overlay is absent. Run → fail.
- [ ] **Step 2 — implement.** Add a `data-testid="output-map-metric-overlay"` card, absolutely positioned top-right inside the map container div (the container must be `relative`; add `relative` if not already). Content: two lines — `Objective` = `result.objective` (locale thousands separators, e.g. `toLocaleString()`), `Weighted avg distance` = `result.metrics.weightedAvgDistance` to one decimal + ` ${distanceUnit}`. Read `distanceUnit` from `useListModels()` for the active `modelId` (mirror how the tab / sibling tabs already resolve it; default `"mi"`). Render only when `result != null`. Style: translucent card (e.g. `bg-background/80 backdrop-blur`), high contrast, `pointer-events-none`, `z`-above the map, small padding — must not block map interaction or overlap the existing top-right controls (offset below them if they share the corner). Because the tab's `result` is `displayedResult`, the overlay follows the result-history stepper automatically — no extra wiring.
- [ ] **Step 3 — verify + commit.** `pnpm --filter studio test OutputMap` + `pnpm run typecheck`. Commit `[B2.1-T2] Output Map floating objective + weighted-avg-distance overlay (item 2)`.
