## Task T2 — DistancesTab merged table (`[bundle6.1-T2]`, item 2 for p-median-us/brazil)

**Files:** `components/workspace/tabs/DistancesTab.tsx` (+ `DistancesTab.test.tsx`).

- [ ] **Step 1: Merged row model**

Replace the two separate sections (reference table + overrides table) with ONE merged, filtered, paginated row list. Build it (resolution #3 — overrides always visible):
```ts
// Complete base-key set BEFORE any view filter (resolution #3).
const baseByKey = new Map(referencePairs.map(p => [pairKey(p.fromId, p.toId), p]));
const overrideByKey = new Map(distanceOverrides.map(o => [pairKey(o.fromId, o.toId), o]));

type MergedRow = {
  fromId: string; toId: string;
  base: number | null;            // reference distance; null = genuinely no base pair (added)
  override?: DistanceOverride;    // present if user overrode / created this pair
};

// 1) base pairs, view-filtered — BUT keep any base pair that carries an override.
const baseRows: MergedRow[] = referencePairs
  .filter(p => {
    const k = pairKey(p.fromId, p.toId);
    const hasOverride = overrideByKey.has(k);
    const passesStatus = !inactiveWarehouseIdSet.has(p.fromId) && !excludedCustomerIdSet.has(p.toId);
    const passesText = p.fromCode.toLowerCase().includes(fromFilter.toLowerCase()) && p.toCode.toLowerCase().includes(toFilter.toLowerCase());
    return (passesStatus || hasOverride) && passesText;   // override forces visibility
  })
  .map(p => ({ fromId: p.fromId, toId: p.toId, base: p.distance, override: overrideByKey.get(pairKey(p.fromId, p.toId)) }));

// 2) added-entity overrides (key NOT in base) appended, applying the text filter.
const addedRows: MergedRow[] = distanceOverrides
  .filter(o => !baseByKey.has(pairKey(o.fromId, o.toId)))
  .filter(o => o.fromId.toLowerCase().includes(fromFilter.toLowerCase()) && o.toId.toLowerCase().includes(toFilter.toLowerCase()))
  .map(o => ({ fromId: o.fromId, toId: o.toId, base: null, override: o }));

const mergedRows = [...baseRows, ...addedRows];
```
Paginate `mergedRows` with the existing single `Pager` (drop the second pager). Keep the clamp-on-shrink + `focusEntityId` one-shot page logic, retargeted to `mergedRows`.

- [ ] **Step 2: Reference load/error states (resolution #6)**

- `referenceQuery.isLoading` → render a loading indicator row/section; the added-entity override rows still render + are editable. Base cells for base rows show a spinner/placeholder, NOT "—".
- `referenceQuery.isError` → an error banner (reuse the existing `distances-reference-error` copy) AND keep override rows editable; base rows' Base cell shows "unavailable".
- Only when the query has SUCCEEDED does a row with `base === null` show "—".
- (For `referenceCapable === false` — p-median-brazil — there ARE no base rows; the table is the override rows only, Base column shows "—" or is omitted.)

- [ ] **Step 3: Customers-styled table + override-cell semantics (resolution #4)**

Render `mergedRows` (paged) in a shadcn `<Table>` matching CustomerTable's look. Columns: From, To, Base distance (read-only), Override, (actions). Per row:
```tsx
<TableRow data-testid={`row-distance-${r.fromId}-${r.toId}`} className={isChangedRow(r) ? "bg-amber-50" : r.override?.estimated ? "bg-sky-50" : undefined}>
  <TableCell className="font-mono text-xs">{displayCodeById?.[r.fromId] ?? r.fromId}{fromUnknown && <AlertTriangle …/>}</TableCell>
  <TableCell className="font-mono text-xs">{displayCodeById?.[r.toId] ?? r.toId}{toUnknown && <AlertTriangle …/>}</TableCell>
  <TableCell className="font-mono text-xs">{baseCell(r) /* number | "—" | "unavailable" | spinner */}</TableCell>
  <TableCell>
    <div className="flex items-center gap-1.5">
      <Input type="number" min={0} value={draftFor(r)} onChange={e => editOverride(r, e.target.value)}
        className="h-7 text-xs w-24 font-mono" data-testid={`input-distance-${r.fromId}-${r.toId}`} />
      {r.override?.estimated && <span … data-testid={`badge-distance-estimated-…`}>Estimated</span>}
      {isChangedRow(r) && <span … data-testid={`badge-distance-changed-…`}>Changed</span>}
    </div>
  </TableCell>
  <TableCell>{(r.override || r.base == null) && <button aria-label="Clear override" onClick={() => clearOverride(r)} data-testid={`button-remove-distance-${r.fromId}-${r.toId}`}><X …/></button>}</TableCell>
</TableRow>
```
Semantics:
- `editOverride(r, raw)`: set `drafts[key]=raw`; parse; if `!Finite || <=0` → keep the draft (inline invalid state) but do NOT commit; else `onChange` upsert `{fromId,toId,distance,estimated:undefined}` into `distanceOverrides`.
- `clearOverride(r)`: `onChange(distanceOverrides.filter(o => key(o)!==key(r)))` AND delete `drafts[key]` (base row stays mounted — a stale draft would otherwise linger). An added-entity row disappears; a base row reverts to base.
- `isChangedRow(r)`: true when the row's override presence/value differs from the SAVED state (`savedDistanceOverrides`) — including a just-cleared-but-unsaved override (saved had it, current doesn't) → still "Changed" until Save. Compare on the merged key including absence.
- `draftFor(r)`: `drafts[key] ?? (r.override ? String(r.override.distance) : "")` — blank when using base.
- `baseCell(r)`: loading → spinner; error → "unavailable"; success + `base==null` → "—"; else `r.base`.

- [ ] **Step 4: Tests (incl. the 4 mandated transitions)**

Reuse the existing `fetchMock`/`renderWithQueryClient` pattern. Cover: merged table shows base rows read-only + editable override column; **add** an override to a base row (row highlights Changed, base still shown); **edit** it; **clear** it (reverts to base, no override); **clear a previously-SAVED override** (row stays Changed until save); an override on an inactive-warehouse / excluded-customer base pair **stays visible** (resolution #3); an added-entity override appends with Base "—"; loading shows spinner not "—", error shows "unavailable"; single pager + From/To filter over the merged set.
