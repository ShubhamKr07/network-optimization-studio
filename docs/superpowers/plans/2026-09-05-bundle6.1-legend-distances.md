## Plan review — resolutions (2026-09-05)

Eight findings; all fixed inline:

1. **[P1] Swatch cells were smaller than the SVGs → overlap.** `customerBubbleSvg`
   emits `2*radius+4` px (QUINTILE_RADII[4]=17 → 38px) and `warehouseTriangleSvg`
   ~22px; the proposed `w-6`(24px)/`w-[14px]` cells clip/overlap (flex centering
   doesn't resize a fixed-size SVG). **Fixed (T1):** status cells → `w-6 h-6`
   (24px, fits 22px); demand cells → `w-6 h-6` with a **uniform legend scale**
   `LEGEND_DEMAND_SCALE = 0.55` applied to every bucket radius
   (`customerBubbleSvg(QUINTILE_RADII[b]*0.55, …)` → max ~22px in 24px) so
   relative size encoding is preserved AND every swatch fits its cell. T3 asserts
   each swatch's bounding box is contained by its cell.
2. **[P1] Clearing a saved override on an inactive/excluded pair made the row
   vanish before Save.** The bypass only fired on `overrideByKey.has(k)`; after
   `clearOverride`, both `passesStatus` and `hasOverride` are false → row gone,
   can't show "Changed". **Fixed (T2):** the visibility bypass is
   `overrideByKey.has(k) || savedByKey.has(k)` (a saved-but-now-absent key is a
   pending deletion) — row stays visible + Changed until Save. Added the combined
   regression test (inactive/excluded + saved override + clear).
3. **[P1] Output legend not wired to the layer toggles.** `NetworkMap` receives
   `showWarehouseMarkers`/`showCustomerMarkers` (from OutputMapTab) but the
   proposed `<MapLegend>` didn't. **Fixed (T1):** pass both into `MapLegend`;
   the Output facility/mine entries gate on `showWarehouseMarkers`, the Customer
   entry on `showCustomerMarkers` (independent). `NetworkMap.test.tsx` covers
   both toggles.
4. **[P1] T3 omitted `bundle6-ui-tweaks.spec.ts`, which asserts 220px
   equal-width + a class-only Output-legend selector — it WILL fail after T1.**
   **Fixed (T3):** T3 explicitly names + updates it (replace the 220px/equal-width
   assertion with the content-fit/`max-w`/alignment + `map-legend` testid
   contract), runs it, and commits its exact path.
5. **[P2] Route-band swatches broke past band 5.** `bandColors[i]` is undefined
   for a 6th band (BAND_COLORS has 5; the map clamps via `getBandColor(i)`).
   **Fixed (T1):** the routes group uses the same `getBandColor(i)` as the map;
   T1 tests a 6-band legend.
6. **[P2] T2b is effectively a no-op — LegDistancesTab already IS Customers-styled.**
   Confirmed: it already uses shadcn `Table`/`TableHeader`/`TableRow`/`TableCell`
   + inline `Input` + `font-mono text-xs` cells + `bg-amber-50` changed rows +
   `max-h-…overflow-y-auto`. **Fixed (T2b):** reframed to an **audit** — apply
   ONLY genuine visual deltas vs the new `DistancesTab`/`CustomerTable`; if there
   are none, RECORD parity and skip the commit (do NOT manufacture an empty

7. **[P2] "Inline invalid state" had no contract.** **Fixed (T2):** an invalid

   (`text-add-distance-error`-style, per-row testid) + keeps the draft visible,

8. **[P2] Filters searched hidden UUIDs, not displayed codes.** **Fixed (T2):**

## Task T2 — DistancesTab merged table (`[bundle6.1-T2]`, item 2 for p-median-us/brazil)

**Files:** `components/workspace/tabs/DistancesTab.tsx` (+ `DistancesTab.test.tsx`).

- [ ] **Step 1: Merged row model**

Replace the two separate sections (reference table + overrides table) with ONE merged, filtered, paginated row list. Build it (resolution #3 — overrides always visible):
```ts
// Complete base-key set BEFORE any view filter (resolution #3).
const baseByKey = new Map(referencePairs.map(p => [pairKey(p.fromId, p.toId), p]));
const overrideByKey = new Map(distanceOverrides.map(o => [pairKey(o.fromId, o.toId), o]));
const savedByKey = new Map(savedDistanceOverrides.map(o => [pairKey(o.fromId, o.toId), o]));

type MergedRow = {
  fromId: string; toId: string;
  base: number | null;            // reference distance; null = genuinely no base pair (added)
  override?: DistanceOverride;    // present if user overrode / created this pair
};

// Filter on the DISPLAYED value, not the hidden uuid (resolution #8).
const displayValue = (id: string) => (displayCodeById?.[id] ?? id).toLowerCase();
const matchesText = (fromDisp: string, toDisp: string) =>
  fromDisp.toLowerCase().includes(fromFilter.toLowerCase()) && toDisp.toLowerCase().includes(toFilter.toLowerCase());

// 1) base pairs, view-filtered — BUT keep any pair carrying a CURRENT or SAVED
//    override visible (resolution #2/#3): a saved-but-now-absent key is a pending
//    deletion that must stay on screen + Changed until Save.
const baseRows: MergedRow[] = referencePairs
  .filter(p => {
    const k = pairKey(p.fromId, p.toId);
    const hasOverrideOrSaved = overrideByKey.has(k) || savedByKey.has(k);
    const passesStatus = !inactiveWarehouseIdSet.has(p.fromId) && !excludedCustomerIdSet.has(p.toId);
    return (passesStatus || hasOverrideOrSaved) && matchesText(p.fromCode, p.toCode);
  })
  .map(p => ({ fromId: p.fromId, toId: p.toId, base: p.distance, override: overrideByKey.get(pairKey(p.fromId, p.toId)) }));

// 2) added-entity overrides (key NOT in base) appended, filtered on DISPLAYED value.
const addedRows: MergedRow[] = distanceOverrides
  .filter(o => !baseByKey.has(pairKey(o.fromId, o.toId)))
  .filter(o => matchesText(displayValue(o.fromId), displayValue(o.toId)))
  .map(o => ({ fromId: o.fromId, toId: o.toId, base: null, override: o }));

const mergedRows = [...baseRows, ...addedRows];
```
Paginate `mergedRows` with the existing single `Pager` (drop the second pager). Keep the clamp-on-shrink + `focusEntityId` one-shot page logic, retargeted to `mergedRows`.

```tsx
<TableRow data-testid={`row-distance-${r.fromId}-${r.toId}`} className={isChangedRow(r) ? "bg-amber-50" : r.override?.estimated ? "bg-sky-50" : undefined}>
  <TableCell className="font-mono text-xs">{displayCodeById?.[r.fromId] ?? r.fromId}{fromUnknown && <AlertTriangle …/>}</TableCell>
  <TableCell className="font-mono text-xs">{displayCodeById?.[r.toId] ?? r.toId}{toUnknown && <AlertTriangle …/>}</TableCell>
  <TableCell className="font-mono text-xs">{baseCell(r) /* number | "—" | "unavailable" | spinner */}</TableCell>
  <TableCell>
    <div className="flex items-center gap-1.5">
      <Input type="number" min={0} value={draftFor(r)} onChange={e => editOverride(r, e.target.value)}
        className="h-7 text-xs w-24 font-mono" data-testid={`input-distance-${r.fromId}-${r.toId}`} />
      {r.override?.estimated && <span … data-testid={`badge-distance-estimated-…`}>Estimated</span>}
      {isChangedRow(r) && <span … data-testid={`badge-distance-changed-…`}>Changed</span>}
    </div>
  </TableCell>
  <TableCell>{(r.override || r.base == null) && <button aria-label="Clear override" onClick={() => clearOverride(r)} data-testid={`button-remove-distance-${r.fromId}-${r.toId}`}><X …/></button>}</TableCell>
</TableRow>
```
Semantics:
- `editOverride(r, raw)`: set `drafts[key]=raw`. **Whole-value** validation
  (resolution #7): `const n = Number(raw.trim())` (NOT `parseFloat`, which
  accepts a numeric prefix like `"12abc"`); if `raw.trim() !== "" && (!Number.isFinite(n) || n <= 0)`
  → mark the row invalid (`invalidKeys.add(key)`), render the input with
  `aria-invalid="true"` + an inline error (`data-testid="text-distance-error-${fromId}-${toId}"`,
  `text-[11px] text-destructive`) + a red ring, and do NOT call `onChange`. Empty
  string is not "invalid" (it's the mid-clear state) — no error, no commit. A
  valid `n > 0` clears the invalid flag and `onChange` upserts
  `{fromId,toId,distance:n,estimated:undefined}`.
- `clearOverride(r)`: `onChange(distanceOverrides.filter(o => key(o)!==key(r)))` AND delete `drafts[key]` (base row stays mounted — a stale draft would otherwise linger). An added-entity row disappears; a base row reverts to base.
- `isChangedRow(r)`: true when the row's override presence/value differs from the SAVED state (`savedDistanceOverrides`) — including a just-cleared-but-unsaved override (saved had it, current doesn't) → still "Changed" until Save. Compare on the merged key including absence.
- `draftFor(r)`: `drafts[key] ?? (r.override ? String(r.override.distance) : "")` — blank when using base.
- `baseCell(r)`: loading → spinner; error → "unavailable"; success + `base==null` → "—"; else `r.base`.
