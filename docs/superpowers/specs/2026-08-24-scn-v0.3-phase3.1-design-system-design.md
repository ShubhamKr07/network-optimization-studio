## Current architecture (why scoping matters)

`artifacts/studio/src/index.css` is Tailwind v4, CSS-variable-driven: a `@theme inline` block maps `--color-primary` etc. to `hsl(var(--primary))`, with actual HSL triples defined in `:root`/`.dark`. Every shadcn primitive (`Button`, `Card`, `Dialog`, `Table`, ...) already consumes these vars — meaning most of the re-theme is just retargeting variable *values*, zero component-class rewrites needed.

There's already a precedent for page-scoped theme overrides: `.studio-lab` remaps the same variable names to a dark "Arcadia" palette, applied only on `Studio.tsx`/`Compare.tsx`'s root div. Global `:root` change would leak the SCN palette onto Landing/auth too — wrong per decision 2. Same mechanism, new class: **`.scn-theme`**, applied to `Workspace.tsx`'s root shell div.

`.studio-lab`/`--arc-*` dead-code cleanup is explicitly NOT part of this phase (Studio.tsx lives until Phase D decommission) — noted as a future cleanup candidate only.

## Fonts

Add `Barlow` + `Barlow Condensed` to the existing Google Fonts `@import` line in `index.css`. New scoped vars inside `.scn-theme`: `--app-font-sans: 'Barlow', system-ui, sans-serif` (overrides body text) and a new `--app-font-heading: 'Barlow Condensed', system-ui, sans-serif`, exposed as a new Tailwind utility `font-heading` (via `@theme inline`'s existing `--font-sans`/`--font-mono` pattern, add `--font-heading: var(--app-font-heading)`). Applied via `font-heading` class on: Workspace top-bar app/scenario name, section headings inside tabs (Cost Breakdown, Service Level, Warehouse Utilization, Scenario Comparison, etc). Body text picks up Barlow automatically through `--app-font-sans` since `body`/`@layer base` already uses `font-sans`.

Existing mono font (Menlo/JetBrains, used for IDs/coordinates) is untouched — wireframe specifies no separate mono token.

## Testing approach

- Existing RTL suites for `Workspace.tsx` and its tabs must stay green — theme is a CSS-variable-value change, not a markup change, so existing `data-testid`/text assertions shouldn't need touching except where the fidelity pass changes copy/labels.
- No new visual-regression tooling introduced (out of scope) — verification is a manual `claude-in-chrome` pass against local dev servers per this repo's established practice for UI-facing phases, comparing rendered Workspace against the 5 wireframe screens side-by-side.
- No solver/Python changes — pytest gate skipped per this repo's established pattern for frontend-only phases.

## What this deliberately does not cover

- Landing.tsx, auth pages (Login/Register), Studio.tsx, Compare.tsx — different scope, explicitly excluded.
- `.studio-lab`/Arcadia dead-code removal — separate cleanup, not bundled here.
- Dark mode for `.scn-theme` — wireframe has no dark variant; not invented.
- Base `--spacing` token change — wireframe's 3.4px-based scale vs Tailwind's 4px-based one; changing it would silently reflow every already-tuned padding/gap app-wide (risk without confirmable payoff). Colors/fonts/radius carry the visual identity; spacing unit does not.
- `uploads/image.png`'s ribbon+sidebar IA — different, unchosen direction.
