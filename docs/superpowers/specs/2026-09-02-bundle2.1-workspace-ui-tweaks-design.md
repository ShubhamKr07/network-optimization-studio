# Bundle 2.1 — Workspace UI tweaks — Design Spec

**Date:** 2026-09-02
**Status:** Draft (awaiting user review)
**Predecessor:** Bundle 2 (merged `29e32ea`, deployed). Five small UI changes on the tabbed Workspace + Landing.

## Goal

Five scoped UI changes: chapter visibility, an Output-Map metric overlay, a text fix, a centered chapter/summary header block, and a header divider-layout fix.

## Changes

### 1. Chapter visibility (Landing)

`artifacts/studio/src/lib/chapters.ts`:
- **Unhide Chapter 5:** remove `hiddenFromLanding: true` from `transport-coal` (`/chapter-5/transport`) and `p-median-brazil` (`/chapter-5/brazil`).
- **Hide Chapter 10:** add `hiddenFromLanding: true` to `two-echelon-gold-au` (`/chapter-10/gold-refinery`).
- Deep links / direct routes remain registered and functional for hidden chapters (same mechanism already used) — only Landing-card visibility changes.
- Landing after: Chapter 3 (Al's/AL's) + both Chapter 5 models visible; Chapter 10 hidden.

### 2. Output-Map floating metric overlay

`artifacts/studio/src/components/workspace/tabs/OutputMapTab.tsx`:
- A small **translucent card, absolutely positioned top-right INSIDE the map container**, over the map, showing two lines: **Objective** (`result.objective`) and **Weighted avg distance** (`result.metrics.weightedAvgDistance`) with the model's distance unit.
- **Reads the currently-displayed result** — the same `result` prop the tab already receives (which the Workspace feeds from `displayedResult`, so the result-history stepper updates the overlay too, honoring the `displayedInputs`/`displayedResult` snapshot principle).
- **Shown only when a result exists** (the Output Map already renders only post-solve; the overlay follows the same `result != null` guard).
- **Unit** from `useListModels()` `distanceUnit` (the tab may already read it for band labels; reuse). Numbers formatted consistently with the existing Cost/Service summary displays (locale thousands separators; distance to one decimal).
- Must not obscure the existing top-right map controls if any — placed as a compact card, `pointer-events-none` so it never blocks map interaction, high-contrast on the tile background.

### 3. "Al's" → "AL's" (Chapter 3)

`artifacts/studio/src/lib/chapters.ts` — Chapter 3 (`p-median-us`):
- `title`: `"Al's Athletics — P-Median"` → `"AL's Athletics — P-Median"`.
- `labHeaderTitle`: `"Al's Athletics · Model Lab"` → `"AL's Athletics · Model Lab"`.
- Grep the whole studio tree for any other `"Al's"` occurrence (tests, fixtures) and update to `"AL's"` so the suite matches.

### 4. Centered chapter + summary in the top bar

`artifacts/studio/src/pages/Workspace.tsx` — the `<header className="h-14 border-b ...">` (currently: back-button + app-name on the left, controls on the right, a `flex-1` spacer between):
- Add a **centered block** in the top bar showing `Chapter N · <one-line description>` — sourced from `chapterForModelId(modelId)` → `${chapter} · ${description}` (the existing per-chapter `description` field is the "quick summary").
- Positioned visually centered in the bar (e.g. absolutely-centered element, so it's independent of the left/right content widths). Small, muted text; **truncate with ellipsis** if it would collide with the left/right content at narrow widths (the description is a full sentence — a centered header slot is tight; truncation keeps the layout stable).
- Applies to all chapters (each has `chapter` + `description`), including Chapter 10 when reached by deep link.

### 5. Header divider no longer crosses the Save / Run Optimizer buttons

`artifacts/studio/src/pages/Workspace.tsx` — same header:
- Today the right-side controls are a `flex-col items-end` (email/logout on the top row, the result-history stepper + "Save as scenario" + "Run Optimizer" on the bottom row). In the `h-14` bar the bottom row sits at the bar's lower edge, so the header's `border-b` visually runs through those buttons.
- **Fix: reposition so the buttons sit cleanly within the bar and the bottom border no longer intersects them** — adjust vertical alignment / row structure (keep the divider). Preserve every existing control, testid, and handler; this is a layout-only change.

## Non-goals / constraints

- No API/contract/solver change — pure frontend (`chapters.ts`, `OutputMapTab.tsx`, `Workspace.tsx` + tests). No `openapi.yaml`, no generated code, no `solve.py`, no dataset.
- `displayedResult` snapshot principle holds for the overlay (item 2).
- All existing header controls/testids/handlers preserved (items 4, 5 are additive/layout-only).
- Gate: `pnpm --filter studio test` + `pnpm run typecheck`. Live-verify in a browser (these are visual changes): Landing card set, the map overlay updating with the stepper, the centered summary, and the divider clearing the buttons.

## Open questions for user review

None outstanding — the four design decisions (item-4 placement = centered in top bar; item-4 content = Chapter N + one-line description; item-2 overlay follows the displayed result; item-5 = reposition buttons, keep divider) were resolved in brainstorming. Flagging one implementation note for awareness: the item-4 centered one-line description is a full sentence in a busy `h-14` bar, so it will truncate on narrower viewports — if that proves too cramped in the live check, the fallback is item-4's sub-bar option (deferred unless needed).
