# SCN v0.3, Task C4.2 — Copy Map to Clipboard Implementation Design

**Status:** Approved · **Date:** 2026-08-24 · **Scope:** implement the clipboard-copy + PNG-download feature on `OutputMapTab.tsx`, per the already-completed research spike.

## Relationship to the spike

`docs/superpowers/specs/2026-08-24-copy-map-clipboard-spike.md` (Phase C, Task 5) already decided: library = `html-to-image` `^1.11.13` (reject `leaflet-image`), and the exact eager-capture code shape required for Safari/Firefox correctness (`navigator.clipboard.write([...])` called synchronously inside the click handler, with the async capture passed as an unawaited `Promise<Blob>` value inside the `ClipboardItem` constructor). This doc does not re-litigate either decision — it resolves the remaining integration questions: where in the component tree this lives, what gets captured, and how it's tested.

## Real finding that simplifies the implementation

The spike's own open item ("`filter` for excluding UI chrome like the layer-toggle checkboxes from the capture... an implementation detail for C4.2") turns out to need no work. `OutputMapTab.tsx`'s existing layout already separates the toggle-checkbox row from the map itself — two sibling `<div>`s, not one nested tree:

```tsx
<div className="h-full flex flex-col gap-3" data-testid="output-map-tab">
  <div className="flex items-center gap-5 flex-wrap flex-shrink-0" data-testid="output-map-toggles">
    {/* checkboxes */}
  </div>
  <div className="flex-1 min-h-0">
    <NetworkMap .../>  {/* or <BrazilMap .../> */}
  </div>
</div>
```

The `flex-1 min-h-0` div is already exactly "the map, nothing else." No `filter` option needed — the capture target is simply that div's ref.

## Files

- **Create `artifacts/studio/src/lib/copyMapToClipboard.ts`**: three pure functions.
  - `captureMapAsBlob(node: HTMLElement): Promise<Blob>` — wraps `htmlToImage.toBlob(node)`, throws if the result is `null` (matches the spike's `if (!blob) throw new Error("capture failed")` guard).
  - `copyMapToClipboard(node: HTMLElement): Promise<"copied" | "downloaded">` — the eager-capture pattern from the spike verbatim: calls `navigator.clipboard.write([...])` synchronously, passes `captureMapAsBlob(node)` as the `ClipboardItem`'s unawaited promise value. On success resolves `"copied"`; on any rejection, calls `downloadMapAsPng(node)` and resolves `"downloaded"` — the function itself embodies the "copy failure falls through to download" rule, so `OutputMapTab.tsx` doesn't need its own try/catch to implement that behavior.
  - `downloadMapAsPng(node: HTMLElement): Promise<void>` — `captureMapAsBlob(node)`, then `URL.createObjectURL` + a synthetic `<a download="output-map.png">` click, mirroring `exportEntity.ts`'s existing blob-download pattern exactly (same `URL.createObjectURL`/`a.click()`/`URL.revokeObjectURL` shape already used elsewhere in this codebase — don't invent a new download mechanism).
  - `isClipboardImageWriteSupported(): boolean` — the static feature-detect (`typeof navigator.clipboard?.write === "function" && typeof window.ClipboardItem === "function"`), called once at render time per the spike's "static capability check, not per-click" rule.

- **Modify `artifacts/studio/src/components/workspace/tabs/OutputMapTab.tsx`**: add a `useRef<HTMLDivElement>` on the existing `flex-1 min-h-0` div (both the `useBrazilMap` branch and the main branch — they're two separate return statements today, both get the same ref/buttons). Add two buttons to each branch's toggle row: "Download PNG" (always rendered) and "Copy to clipboard" (rendered only when `isClipboardImageWriteSupported()` returns true, checked once via `useState(() => isClipboardImageWriteSupported())` so it's a stable per-mount value, not re-evaluated every render).

- **Modify `artifacts/studio/package.json`**: add `"html-to-image": "^1.11.13"` to `dependencies` (matching the spike's exact pinning-convention recommendation).

## Toast feedback

This codebase already has a `toast()` helper (`@/hooks/use-toast`, used throughout `Workspace.tsx`/`ImportDialog.tsx`). `copyMapToClipboard`'s resolved value (`"copied"` | `"downloaded"`) drives which toast the click handler shows — `"Map copied to clipboard"` or `"Clipboard unavailable — downloaded as PNG instead"` — so the user always gets explicit feedback about which of the two things actually happened, never a silent success.

## Testing approach

- `copyMapToClipboard.test.ts`: mock `html-to-image`'s `toBlob` (vitest module mock) and `navigator.clipboard`/`window.ClipboardItem` (test-local stubs, restored after each test — this repo has no existing Clipboard API mock to reuse, first test file to need one). Key assertions: `clipboard.write` is called synchronously within the same microtask as the function call (not after an `await` on the capture) — the load-bearing behavior the whole spike exists to guarantee; a rejected `clipboard.write` results in `downloadMapAsPng`'s side effect (an anchor `click()`) actually firing; `captureMapAsBlob` throws when `toBlob` resolves `null`.
- `OutputMapTab.test.tsx` (existing file, extend it): "Copy to clipboard" button absent when `isClipboardImageWriteSupported` is stubbed false; present and wired to `copyMapToClipboard` when stubbed true; "Download PNG" always present regardless.

## What this design deliberately does not cover

- `html-to-image`'s `Options` tuning (pixel ratio, `backgroundColor`) — defaults are used; revisit only if a real captured image looks wrong once this ships, not speculatively.
- Any change to `NetworkMap.tsx`/`BrazilMap.tsx` themselves — capture operates on the existing rendered DOM, no map-component changes needed.
- Any other tab besides Output Map — the source plan's C4.1/C4.2 scope this to the map specifically.
