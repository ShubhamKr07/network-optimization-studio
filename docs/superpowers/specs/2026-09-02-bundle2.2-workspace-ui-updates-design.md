## Global Constraints

- **DD-1:** base dataset files under `solvers/*/dataset/*.json` are never mutated. Reference distances read from the loaded dataset; overrides live only in scenario `inputs`.
- **No modelId hardcoding for capability gates** (repo's most-documented recurring bug class). Use manifest `capabilities` / scenario config, never `modelId === "..."` for per-model behavior.
- **Never edit generated code** (`lib/api-zod/src/generated/`, `lib/api-client-react/src/generated/`). Contract change = edit `openapi.yaml`, re-run Orval, commit spec + regen together.
- Ownership/anti-enumeration unchanged (404 never 403). Solver contract untouched — `e2e_accuracy.py` must stay green if any dataset/Python touched (it isn't expected to be here).
- Distance unit is model-driven (`manifest.distanceUnit`), already resolved via `useListModels()`; new distance UI reuses that, no hardcoded "mi".

## The 15 Updates

### Group A — Maps

**A1 (item 2/3) — Input Map layer toggles → checkboxes + legend follows toggles.**
Replace `ToggleChip` buttons for the three **layer** toggles (Warehouses, Customers, Show-inactive) with shadcn `Checkbox` rows, visually matching `OutputMapTab`'s toggle group. The two place-pin controls (place-wh / place-cs) stay action buttons — they are one-shot placement actions, not layer toggles. `MapLegend` receives the toggle state and hides swatch groups for layers that are toggled off (e.g. Customers off → hide demand-quintile bubbles + customer status swatches; Warehouses off → hide warehouse status swatches).

**A2 (item 4) — "Size customers by demand" toggle, Input Map only, default ON.**
New `Checkbox` in the Input Map toolbar. State `sizeByDemand`, default `true`. When ON: current quintile radius behavior (`EntityMarkers`/`makeQuintileRadius`). When OFF: every customer marker renders at a single fixed radius. Output Map is out of scope for this toggle (keeps its current `scaleDemand`). Legend's demand-bubble section renders only when `sizeByDemand` is ON (and Customers layer is on).

**A3 (item 10) — Customer Active/Excluded status in input-map dialogs.**
Add a status control (Active / Excluded, two-state — customers have no "forced open") to **both** `EditCustomerDialog` and `CreateEntityDialog`'s customer branch. Persists to `customerOverrides[].status`. Backend: confirm `customerOverrides` item schema carries a `status` field with values `active | excluded` (add to `openapi.yaml` + Zod validator if absent; regen). Excluded customers are already dropped from the solve (existing override semantics) — this just gives the map dialog a control to set it. Excluded customers render with the inactive/excluded visual treatment on the input map (reuse existing inactive styling).

**A4 (item 12) — Route hover box on the Output Map.**
Add a react-leaflet `<Tooltip>` (translucent, `pointer-events-none`) to each route polyline in `NetworkMap.tsx:442-479`. Content: `{fromCity} → {toCity}` and the leg length in the model's distance unit (`{dist} mi`). Cities resolved from the edge's `fromId`/`toId` against the effective dataset (same lookup the popup/markers already use). No change to click-based `CustomerPopup`.

### Group B — Output tabs (p-median-us, capability/config-gated)

**B1 (item 5) — Hide Utilization when `capacityMode === "none"`.**
`OpenWarehousesTab` drops the Utilization column (header `56-58` + cell `66`) when the active scenario's `inputs.capacityMode === "none"`. Config-driven (reads the scenario inputs already available to the tab), applies to any p-median model whose scenario has no capacity; two-echelon and capacitated scenarios keep the column. Not a modelId check.

**B2 (item 6) — Flows tab gated out of the sidebar for models without it.**
Gate the sidebar **output entries** by the active model's manifest `capabilities.outputGrids`. p-median-us `outputGrids` = `[openWarehouses, assignments, costSummary, serviceStats]` (no `flows`) → the Flows sidebar entry no longer renders. Closes the known C6.1 follow-up (sidebar previously showed all 5 regardless). The content-level gate at `2122-2148` stays as defense-in-depth. Models with `flows` in `outputGrids` (transport-coal, two-echelon) still show it.

**B3 (item 7) — Distances tab read-only reference table.**
Above (or beside) the existing editable override add-row section, render a **read-only** reference table of base distances for every **active** (potential + fixed-open, i.e. non-inactive) warehouse × customer pair, read from the effective dataset. Columns: From (warehouse, display code) / To (customer, display code) / Distance (model unit). Scrollable, virtualized (dataset is up to ~26×200 for active WHs on p-median-us). Clearly labelled "Base distances (reference)". The editable `distanceOverrides` grid is unchanged and stays the source of truth for overrides. This is display-only — reading base data, writing nothing.

**B4 (item 8) — Solution Summary moved after Output Map.**
Reorder `OUTPUT_ENTRIES` so `cost-summary` (Solution Summary) sits immediately after `Output Map`: Output Map, Solution Summary, Open Warehouses, Customer Assignments, [Flows], Service Stats.

**B5 (item 9) — Open-warehouse set per scenario in Solution Summary compare.**
In `CostSummaryTab` **compare mode**, add a row immediately after "Weighted avg. distance" listing each selected scenario's set of open warehouses **by city name** (derived from unique `edges[].fromId` → dataset city lookup; for two-echelon this is the open refineries, consistent with the existing "Open facilities" concept). Single-scenario mode unchanged.

**B6 (item 11) — Display ID (not uid) for user-created warehouses.**
`OpenWarehousesTab` (`64`) and `AssignmentsTab` (`47-48`) map `fromId` (and `toId` where a warehouse) through a `displayCodeById` lookup (same pattern `DistancesTab` already uses) so user-created warehouses show their human ID, not the opaque `aw-…` uid. Base-dataset entities are unaffected (their id === display code).

### Group C — App chrome

**C1 (item 1) — Global footer.**
Bottom-center footer on **every page** (Landing, Login, Register, Workspace, Studio, Compare): the copyright symbol `©` followed by `Developed by hx1`. Implement once as a shared `AppFooter` component mounted at the app shell level (so it appears on all routes) or a fixed/sticky bottom-center element; must not overlap Workspace map content or the Workspace footer area (thin, non-intrusive). Under the `.scn-theme` scope it inherits theme fonts/colors; on non-themed pages it uses default styling.

**C2 (item 13/14/15) — Workspace header rework.**
- Remove the title/subtitle block (`2202-2205`, "SCND Optimization Studio" / "By Prof. Michael Watson").
- Scenario `<select>` (`2206-2223`) moves to the **left corner** (after the back-arrow).
- Chapter+summary block (`2229-2242`) stays **centered**, now **untruncated** (drop `max-w-[38%] truncate`; allow full text, wrap if needed) — "show the complete line."
- User name + Logout (`2244-2255`) move to the **top-right corner**.
- The result-history stepper + "Save as scenario" + Run-Optimizer cluster stay **exactly where they are** (unchanged position, to the left of the Run Optimizer button). Explicit user constraint.

- Brazil-specific input map (still has no `GET /dataset` browsing endpoint on that path; unaffected — these changes touch shared components and p-median-us).
