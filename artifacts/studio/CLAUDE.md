# Studio frontend (`artifacts/studio/`) — gotchas

Moved out of the root `CLAUDE.md` so it loads only when working under this directory. The root file's Hard rules, Branch discipline, and cross-cutting Gotchas still apply. New gotchas scoped to this directory go here (hard rule #9).

- **A `<Dialog>` triggered from an early-return branch must also be RENDERED in that same branch.** `Studio.tsx`'s "Create first scenario" button (in the `!scenarios?.length` and Brazil-empty early returns) called `setShowCreateDialog(true)` correctly, but the actual `<Dialog>` JSX lived only in the component's main `return`, which those early returns never reach — so the state changed with zero errors, but there was no Dialog mounted anywhere to display it. Silent, first-run-blocking: any brand-new account (or the empty Brazil-lab state) could never create a scenario at all. Pre-existing bug, unrelated to the same-day auth-routing fix — confirmed via git log that `Studio.tsx` predates it. Never caught because `Studio.test.tsx` always pre-seeded at least one scenario in its mocks; nothing exercised the true zero-scenario first-render path, and no manual test in this project's history ever used a genuinely empty account against a fresh production DB until today's Render deployment. Fixed by extracting the dialog into one `const` referenced from all three return branches (both early returns + main), so it's always in the tree regardless of which branch renders. New test in `Studio.test.tsx` (`"Studio — empty scenarios"`) covers exactly this path. **Lesson: any state-driven UI (dialog, drawer, tooltip) referenced from multiple early-return branches needs its trigger AND its render to be reachable from every branch that can call the trigger — don't assume "it's a hooks thing that always applies," check the JSX tree, not just the state.**
- **`Gate()` in `App.tsx` must be ONE `<Switch>` with a fixed route set — never two swappable trees keyed on auth state.** Real production bug (found post-deploy, unrelated to Render infra): `Gate()` used to render either `AuthedRouter` or `UnauthedRouter` — two entirely separate `<Switch>` trees — based on `useGetCurrentAuthUser()`'s data. wouter's `<Switch>`/`<Route>` subscribe to the current location independently of their parent, so the instant any handler called `navigate(...)` (login/register success, logout), the OLD tree — still mounted at that exact instant, since `Gate()` itself hadn't re-rendered with fresh auth data yet — reacted to the brand-new location on its own via its own subscription, matched it against its OWN route set, found nothing, and its own catch-all fired a REAL navigation (e.g. `UnauthedRouter`'s `<Redirect to="/login">`) before the swap to the correct tree ever happened. By the time `Gate()` did swap, the URL had already been moved to a path the NEW tree has no route for → its own NotFound catch-all. Reproduced and confirmed via `history.pushState`/`replaceState` instrumentation in a real deployed browser (not reproducible by a fully-mocked-router unit test). Fixed by merging into one always-mounted `<Switch>` where every path (`/`, `/login`, `/register`, chapter paths, `/compare`, catch-all) is always a real `Route` regardless of auth state — only the per-route *content* branches on `user` (page vs `<Redirect>`), so a transitional render always resolves to a valid redirect, never a dead end. `writing setQueryData({user: ...})` synchronously in `onSuccess` (instead of `invalidateQueries` + waiting on a refetch) is still correct practice and kept — it narrows the window — but does not by itself close this race; the single-`Switch` structure is what actually closes it. See `App.test.tsx` (uses real wouter via `wouter/memory-location`, not a mocked router) for the regression coverage.
- **A RATE converts as the RECIPROCAL of a distance — never run a $/unit-distance value through `UnitApi.toDisplay`/`fromDisplay`.** Those multiply, which is right for a distance and wrong for anything priced *per* distance: 0.07 $/ton-mi would render as 0.1127 $/ton-km (freight getting more expensive because a display toggle flipped) instead of the correct 0.0435. Derive the pair from the same authority rather than hardcoding 1.609344 — `rate / toDisplay(1, canonical)` and `rate * toDisplay(1, canonical)` (`artifacts/studio/src/lib/transportCosts.ts`'s `rateConversion`). A value with no distance dimension at all (a $/ton minimum charge) needs an identity pair so the toggle leaves it alone. The draft machinery is shared: pass `convert` into `useDistanceDraft` (ch9-tc) rather than writing a parallel hook. **The semantic no-op guard now lives INSIDE `useDistanceDraft.commit()`** (WF-6, inverting what this gotcha used to say), so all **15** call sites inherit one and no new caller needs a bespoke copy — `commit()` fires for every grammar-complete draft, and before WF-6 retyping the identical displayed text committed `650 → 650.0000000000001`, flipping the scenario dirty and retargeting a band to a float. The hook's guard compares at `roundForFile`'s 4 dp in **canonical** space, which is the only space it can know. A caller still needs its own guard when its comparison space differs — for a RATE, `toDisplay` *divides*, so 4 dp in display space is a ~1.6× coarser canonical tolerance, and `TransportCostsTab`'s `commitField` is deliberately kept on top of the hook's as the coarser of the two (an AND of two independent detectors, not dead redundancy). Never compare by raw string: `0.0700` and `0.07` are the same value, and a cross-unit round trip legitimately lands on `0.070006…`.
- **A mutation's `onError` is not optional, and only a SOURCE-READING guard can keep it that way — no behavioural test can see a handler that was never written.** Before WF-9 this app had six `.mutate()` sites in `Workspace.tsx` with no `onError` at all and three places extracting `err.message`, which is `custom-fetch.ts`'s `buildErrorMessage` output — so the student was shown `HTTP 422 Unprocessable Content: [{"code":"too_small",…}]` or, more often, nothing. Every write failure goes through **`lib/describeWriteError.ts`**, and the server owns the sentence (see `artifacts/api-server/CLAUDE.md`); never render `err.message` from an API rejection. Enforcement is two source-reading tests, and the split between them is the lesson. `__tests__/mutationErrorSurface.test.ts` reads **only `Workspace.tsx`** and fails on a `.mutate(` with no `onError` before the next one, on a handler rendering a raw message instead of `describeWriteError`, and on a `.catch(` whose body does nothing with the error it caught (`ALLOWED_EMPTY_CATCHES` is currently empty — keep it that way or name the exception). `__tests__/rawErrorMessageSurface.test.ts` **walks the whole `src/` tree** for the `instanceof Error ? …message` fallback, with a two-entry allow-list (`pages/Studio.tsx` — dead code pending Phase D; `components/workspace/tabs/OutputMapTab.tsx`), each carrying a written reason. **Prefer the tree walk over a named file list.** The file-scoped guard is exactly why WF-3 shipped `ImportDialog.tsx` and `lib/exportEntity.ts` still dumping `HTTP 422 …` — both are live write paths outside `Workspace.tsx`, so a guard scoped to that one file was blind to them by construction. Both tests also carry a **non-vacuity** case (it really finds mutate sites / source files to scan) and the allow-list test asserts each entry *still contains* the pattern it exempts, so fixing one surfaces as a stale-entry cleanup instead of silently passing.
- **A test that cannot fail is not coverage, however much of it you write — and jsdom guarantees this for anything whose behaviour lives in CSS or in a stubbed browser API.** `src/__tests__/setup.ts` installs a no-op `ResizeObserver` (Radix needs one to exist), and no Tailwind stylesheet is loaded, so `group-hover`, `opacity-0`, `pointer-events-none` and every container-resize path are inert in RTL. A feature resting on those mechanisms can carry a large, green, structurally useless unit suite. The miniature version is an assertion: `expect(el).toBeVisible()` on an `opacity-0` element passes, because Playwright's visibility check ignores opacity — an assertion that cannot fail. Both shipped in the same week (SBR bundle, `empty-first-run-workspace.spec.ts:53`). If the mechanism is CSS or a browser API, the covering test has to be a real-browser one.
